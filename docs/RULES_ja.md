# scPEFT 記述ルール（Geneformer ルールの適用先）

> # ⛔ 最初に必ずこのページを読んでください
>
> **scPEFT に関する作業、記述、レビューを始める前に、必ずこのページを読んでください。**
> このリポジトリの作業では、**Geneformer の記述ルールを、Geneformer に固有でない限り適用します**。
> 親のルールブックは `research/Geneformer/docs/isp/style-guide.md`（以下「親ルール」）です。
> 迷ったときは、親ルールを見てください。適用の有無は [§2](#2-親ルールのうち適用しないもの) と [§3](#3-親ルールのうち適用するもの) にまとめてあります。
>
> - 判断に迷ったら、**推測で埋めずに「判定不能」と書いてください**。
> - **ミスはやむを得ませんが、結果の捏造につながる作為的な修正は絶対に行いません**（[§1](#1-最優先の遵守項目)）。

---

# 1. 最優先の遵守項目

**この 5 項目は、このページの他のどの規則よりも優先します。**

1. **数値を変える処理を入れたら、値を変えていないことを実測で確かめてから報告します。**
   確かめ方の例: 実行条件（forward バッチサイズ、対象細胞の集合、対象遺伝子の集合）を変えて、
   同じ値が出ることを確認します。
2. **辻褄合わせの処理を入れません。** 切り詰める、穴を埋める、例外を握り潰す、といった処理で
   「通る」ようにしません。**前提が崩れているときは、黙って通さず停止させます。**
3. **「実行が通ったこと」を「値が正しいこと」の根拠にしません。** 通ったことを報告するときは、
   何を確かめたのかを添えます。
4. **誤りが見つかったら、訂正前と訂正後の数値を並べて報告します。** 自分の誤りを
   「都合の良い処理」と言い換えて軽く扱いません。
5. **自分の誤りを記録に残します。** コミットメッセージには、何が欠陥で、何が変わったかを書きます。

> **この規則の由来（実例）**: ミニバッチごとに長さの違うコサイン類似を `torch.cat` で
> 連結するために、最短に切り詰める処理を入れたことがあります。これはパディングを落とす
> つもりが**実データを削っていました**（3850 対 2741 位置、系列の約 3 分の 1）。
> しかも切り詰め先が「その実行に含まれる細胞の最短」だったため、**同じ細胞でも同梱する
> 細胞次第で値が変わる**状態でした（平均 0.989968 が 0.996946 に移動）。
> 正しい処置は、**幅を最初から揃える**ことです（[§4-6](#4-6-系列長の整合)。

# 4. このリポジトリ固有のルール

## 4-1. デバイス

- **デバイスの決定は 1 箇所（`scpeft_mps/device.py`）だけで行います。** 選択順は MPS、CUDA、CPU です。
- **`cuda` を直接書いたコードを残しません。** 追加・修正したら `patches/apply_mps_patch.py --check` で確認します。
- MPS には制約があります（`float64` 非対応、attention テンソルが `INT_MAX` を超えると即落ち）。
  詳細は `docs/MPS.md` にあります。**316M 級では系列長 4,096 で forward バッチ 4 が上限**です。

## 4-2. パッチと再適用

- パッチは `patches/apply_mps_patch.py` で適用します。**`--check` で件数、`--revert` で復元**です。
- **適用したファイルは必ず構文を確認します**（`python -m py_compile`）。置換で壊れる事例があるためです。
- **上流のファイルを取り直したら再適用します。** `--revert` を忘れると二重適用の原因になります。
- 上流の欠陥を直すときは、**置換規則の上に理由をコメントで書き残します**。理由のない置換を残しません。

## 4-3. 置き場所

| 種類 | 置き場所 | コミット |
|---|---|---|
| 5 タスクのスクリプト | `scripts/` | する |
| パッチ | `patches/` | する |
| 文書 | `docs/` | する |
| 出力（埋め込み、`*.dataset`、統計、図） | `outputs/` | **しない**（`.gitignore`） |
| 実行ログ | `logs/` | **しない**（`.gitignore`） |
| 展開した vendored ツリー、`.orig` | リポジトリ直下、`*.py.orig` | **しない**（`.gitignore`） |

## 4-4. モデルと辞書

- `model_directory` には**モデル本体のフォルダ**を渡します（親フォルダではありません）。
- トークン辞書は **gc104M を明示的に渡します**。摂動器は既定で別の辞書を読むため、埋め込み抽出と
  摂動で同じ辞書を渡さないとトークン ID が一致しません。
- `datasets` は **4.0.0** を使います。

## 4-5. メモリと時間の記録

- **各タスクのピークメモリと所要時間を記録します。** 記録は `outputs/<タスク名>_memory.json` です。
- ピークは**細胞数ではなく `forward バッチサイズ × ヘッド数 × 系列長² × バイト数` で決まります**。
  条件（モデル、系列長、バッチサイズ、細胞数、遺伝子数）を添えずに数値を引用しません。
- 出力ファイル名は**スクリプト名**（`sys.argv[0]`）で決めます。`__module__` は全スクリプトで
  `__main__` になり、互いに上書きされます。

## 4-6. 系列長の整合

- **長さを揃える必要があるときは、幅を最初から揃えます。** 事後に切り詰めて揃えません。
  切り詰めはパディングを落とすつもりで実データを削り、しかも同梱する細胞次第で値が変わります。
- **比較する 2 つのテンソルの長さが食い違ったら、黙って通さず停止させます。**
- パディングは下流で「その細胞の元の長さ」により落とされます。**幅そのものは値に影響しません**。

## 4-7. 摂動の実行

- 摂動は**複数の遺伝子をまとめて**渡せます（Geneformer のリスト指定は同時摂動です）。
  1 遺伝子ずつに分ける場合は `--per-gene` を明示します。
- 同時摂動は**指定した全遺伝子を持つ細胞**だけを対象にします。実行前に共発現細胞数を表示し、
  0 のときは理由を明示して停止します。
- 集計モードは実行内容で決まります（状態対があれば `goal_state_shift`、遺伝子を明示した摂動は
  `aggregate_data`）。`aggregate_data` は `genes_to_perturb="all"` を受け付けません。

# 5. 用語

| 使う表記 | 意味（初出で添える説明） | 使わない表記 |
|---|---|---|
| **5 タスク** | 細胞型同定、バッチ補正、in silico 摂動、細胞集団発見、マーカー遺伝子検出 | ベンチマーク項目 |
| **in silico 摂動** | 計算機上で遺伝子を削除・過剰発現させる解析 | 摂動予測（別のタスクを指すため） |
| **埋め込み抽出** | モデルの中間表現を取り出す操作 | 特徴抽出、エンコード |
| **forward バッチサイズ** | モデルに一度に通す細胞数の単位 | バッチサイズ（キー名 `batch` は可） |
| **ピークメモリ** | 実行中の最大メモリ使用量 | 最大メモリ、必要メモリ |
| **判定の語彙** | 合格、不合格、未検証、判定不能 | 保留、未達、未実施 |
| **根拠の種類** | A（実測）、B（借用、要確認）、C（未確立） | エビデンスレベル |

# 6. 報告の型（このリポジトリの標準）

結果を報告するときは、次の 4 つを 1 組にします。どれか欠けると検証できません。

1. **観点**: 何を評価するか。
2. **基準**: 合格ライン。**実測（A）でない基準では判定しません**。
3. **実測**: 数値と、それを出した条件（モデル、系列長、バッチサイズ、細胞数、遺伝子数、実行時間、ピークメモリ）。
4. **判定**: 合格・不合格・未検証・判定不能 のいずれか 1 語。

**誤りを訂正したときは、訂正前と訂正後の数値を並べて書き、何が変わったかを書きます。**

# 7. 変更の手順

1. このページを直します（[§1](#1-最優先の遵守項目) の 5 項目は変更しません）。
2. 親ルールとの対応が変わる場合は、**親ルールの `§G`（派生リポジトリへの適用）も直します**。
3. 数値を変える変更を入れた場合は、**値を変えていないことを実測で確かめてから**コミットします。
